# linux-vsr: нативный слой аппаратного апскейла видео для linux

linux-vsr - модульный графический слой и драйверная прослойка для автоматического аппаратного масштабирования и повышения четкости видео (аналог технологии nvidia rtx video super resolution) на уровне всей системы linux.

работает с любыми браузерами (zen browser, firefox, chromium, chrome, brave) и медиаплеерами (mpv).

проект перехватывает компиляцию opengl/egl-шейдеров на лету и заменяет стандартную билинейную интерполяцию видеотекстуры на amd fidelityfx contrast adaptive sharpening (cas), edge-adaptive spatial upsampling (easu) или экспериментальный directional sharpen прямо в графическом конвейере видеокарты без копирования кадров. Лаунчер умеет направить Chromium через ANGLE/OpenGL к hook; проверенный видеопуть сейчас покрывает Firefox и Zen WebRender, а сигнатуры Chromium и чистый Vulkan ещё интегрируются.

---

### ключевые особенности

* нулевой оверхед (0.02 мс на кадр): апскейлер встраивается в исходный фрагментный шейдер видеокомпозитора, без выделения дополнительных fbo и копирования видеопамяти.
* горячая перезагрузка (hot reload): подхват изменений резкости и режимов из файла конфигурации на лету без перезапуска браузера.
* визуальный индикатор (badge watermark): встроенный в шейдер угловой индикатор для мгновенного визуального контроля активности апскейла.
* модульный монолит на чистом c: строгая изоляция модулей, безопасная работа с памятью и арифметикой (`safety`), сокрытие внутренних символов (`-fvisibility=hidden`).
* vendor-aware браузерный путь: автоопределение AMD/NVIDIA через DRM и ручной выбор через `VSR_BACKEND`.
* готовый cli-инструментарий: лаунчер с пробитием песочниц, cli-пульт управления профилями и интерактивный мастер дампа/проверки.

### архитектура: модульный монолит

код спроектирован по модульному принципу с разделением ответственности:

```
linux-vsr/
├── include/vsr/
│   ├── config.h      # парсер ini-файлов, переменных окружения и профилей
│   ├── hook.h        # перехватчик opengl/egl/dlsym вызовов
│   ├── logger.h      # форматированный диагностический вывод с троттлингом
│   ├── patcher.h     # синтаксический анализ glsl и замена семплирования
│   ├── safety.h      # безопасная арифметика, лимиты памяти и clamp
│   └── shaders.h     # генератор кода шейдеров cas/easu/directional с вотермарком
├── src/
│   ├── config.c      # реализация загрузки, валидации и сохранения конфига
│   ├── hook.c        # интерпозиция glshadersource, glcompileshader, eglGetProcAddress
│   ├── logger.c      # реализация терминального логгера
│   ├── main.c        # конструктор и деструктор динамической библиотеки
│   ├── patcher.c     # парсинг скобок и внедрение шейдерных функций
│   ├── safety.c      # проверки переполнения, безопасный strdup/malloc
│   └── shaders.c     # сборка glsl с фиксацией c-локали для чисел
├── tests/
│   ├── test_config.c # тесты парсинга настроек и ini-файлов
│   ├── test_patcher.c# тесты распознавания webrender и замены семплеров
│   ├── test_runner.c # точка входа модульного тестирования
│   ├── test_safety.c # тесты безопасной арифметики и лимитов
│   └── test_shaders.c# тесты генератора cas и easu шейдеров
├── bin/
│   ├── linux-vsr     # универсальный скрипт запуска и gdb-инжектор
│   ├── linux-vsr-ctl # cli-утилита горячего переключения настроек и профилей
│   └── linux-vsr-setup # интерактивный мастер проверки и создания .desktop файла
├── shaders/
│   ├── cas.glsl      # эталонный шейдер amd fidelityfx cas
│   └── fsr_easu.glsl # эталонный шейдер directional spatial filter
└── Makefile          # строгие флаги сборки (-Wall -Wextra -Werror)
```

### конвейер обработки данных (pipeline)

```
видеопоток (h.264 / vp9 / av1)
       │
       ▼
аппаратный декодер (nvidia nvdec через libva-nvidia-driver)
       │  прямой zero-copy в vram (nv12 / p010)
       ▼
композитор браузера (webrender / opengl / egl)
       │
       ▼
прослойка linux-vsr (libvsr.so через ld_preload)
       │  перехватывает glshadersource
       │  заменяет билинейный семплинг luma на fidelityfx cas / easu / directional
       ▼
выполнение на gpu (шейдерные блоки видеокарты)
       │  время обработки кадра: 0.02 мс
       ▼
вывод на экран (композитор wayland / x11)
```

### сборка

требования:
* gcc или clang;
* make.

сборка библиотеки:
```bash
make -j$(nproc)
```
сборка занимает меньше 0.1 секунды и создает файл `libvsr.so`.

### запуск и инструменты

#### 1. универсальный лаунчер (`linux-vsr`)

автоматически находит установленный браузер, пробивает песочницы для дочерних gpu-процессов и подгружает библиотеку:

```bash
# запуск zen browser (по умолчанию)
./bin/linux-vsr

# запуск mozilla firefox
./bin/linux-vsr firefox

# запуск chromium
./bin/linux-vsr chromium

# запуск mpv
./bin/linux-vsr mpv https://example.com/video.mp4

# инжект в уже запущенный процесс через gdb
./bin/linux-vsr attach <PID>
```

#### 2. управление на лету (`linux-vsr-ctl`)

позволяет менять параметры и профили без перезапуска браузера (изменения подхватываются хуком примерно за 1 секунду):

```bash
# интерактивное консольное меню
./bin/linux-vsr-ctl menu

# смена резкости (от 0.0 до 0.5)
./bin/linux-vsr-ctl sharpness 0.30

# переключение алгоритма (cas / easu / directional / off)
./bin/linux-vsr-ctl mode cas

# включение/выключение углового индикатора
./bin/linux-vsr-ctl watermark off

# сохранение и переключение профилей
./bin/linux-vsr-ctl save anime
./bin/linux-vsr-ctl use anime
```

#### 3. мастер проверки и настройки (`linux-vsr-setup`)

интерактивный скрипт для сбора дампа шейдеров, проверки факта перехвата и создания ярлыка:

```bash
# запуск проверки
./bin/linux-vsr-setup

# создание .desktop ярлыка для системного меню приложений
./bin/linux-vsr-setup --install-desktop zen-browser
```

### конфигурация

настройки хранятся в `~/.config/linux-vsr/config.ini` (или задаются через переменные окружения):

| параметр / переменная | значение по умолчанию | описание |
|---|---|---|
| `enable` / `VSR_ENABLE` | `1` | включение (`1`) или отключение (`0`) обработки |
| `mode` / `VSR_MODE` | `cas` | алгоритм апскейла (`cas`, `easu`, `directional`, `off`); `directional` — экспериментальный GLSL-фильтр направленной резкости для любых GPU |
| `backend` / `VSR_BACKEND` | `auto` | аппаратный путь (`auto`, `amd`, `nvidia`, `generic`) |
| `sharpness` / `VSR_SHARPNESS` | `0.15` | сила адаптивной резкости (от `0.0` до `0.50`) |
| `debug` / `VSR_DEBUG` | `1` | вывод отладочных сообщений в stderr |
| `watermark` / `VSR_WATERMARK` | `1` | отображение полосатого индикатора в углу видео |
| `watermark_opacity` / `VSR_WATERMARK_OPACITY` | `0.45` | прозрачность индикатора (от `0.05` до `1.0`) |
| `watermark_size` / `VSR_WATERMARK_SIZE` | `0.06` | относительный размер индикатора |
| `model` / `VSR_MODEL` | `""` | путь к скомпилированному tensorrt engine |
| `VSR_CONFIG` | `~/.config/linux-vsr/config.ini` | переопределение пути к файлу конфигурации |

пример запуска с переопределением:
```bash
VSR_MODE=cas VSR_SHARPNESS=0.32 VSR_WATERMARK=0 ./bin/linux-vsr

# принудительный backend для диагностики и A/B-проверок
VSR_BACKEND=nvidia ./bin/linux-vsr
```

### текущие проблемы и ограничения

* **песочницы браузера (security trade-off):** для доставки `LD_PRELOAD` в дочерние gpu/rdd-процессы gecko требуется отключать внутренние песочницы (`MOZ_DISABLE_*_SANDBOX=1`). это осознанный компромисс безопасности, о котором браузер может предупреждать при запуске.
* **работа с уже запущенным браузером:** если zen или firefox уже запущен в системе, вызов `./bin/linux-vsr` без изоляции профиля передаст команду работающему процессу без нашего хука. требуется либо запускать браузер через скрипт изначально, либо использовать инжект через `./bin/linux-vsr attach <pid>`.
* **выбор браузерного backend:** Firefox и Zen используют штатный WebRender/OpenGL. При включённом `VSR_CHROMIUM_GL` лаунчер запускает Chromium и Brave через ANGLE/OpenGL под Xwayland, но сигнатуры видеошейдеров Chromium требуют проверки для каждой связки GPU/драйвер; чистый Vulkan/Graphite остаётся отдельным путём.
* **отсутствие in-video gui:** на уровне перехвата компиляции `glShaderSource` невозможно отрендерить интерактивные кнопки или кликабельное меню поверх видеокадра. все управление вынесено в cli-утилиту `linux-vsr-ctl`.
* **vulkan бэкенд:** при принудительном переключении браузера на чистый vulkan (`gfx.webrender.all=true` с wgpu/vulkan) перехват через opengl/egl не срабатывает. требуется отдельный слой перехвата `vkCreateShaderModule` и патчинга spir-v.
* **nvidia и amd в браузере:** текущий нативный hook применяет GLSL-фрагментный путь на обоих вендорах и записывает определённый DRM backend. Проприетарный AI-путь NVIDIA RTX Video Super Resolution требует отдельной compute/SDK-интеграции; `VSR_BACKEND=nvidia` не выдаёт текущий shader path за эту модель.
* **ai-рантайм (tensorrt):** скомпилированные `.engine` модели для rtx 5070 подготовлены в репозитории, но сквозной инференс через cuda/opengl interop прямо в видеопотоке пока находится в процессе интеграции.
